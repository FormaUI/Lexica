# Type selectors

<a id="runtime-type-selectors"></a>

A **type selector** maps keys to types, so a function's fixed argument can choose the type the function answers, as [type selectors](../language/vocabulary.md#vocabulary-type-selectors) set out in the language contract. A module declares the selector and the keys it maps; a key's type is what a script reads where the function is given that key.

- **Declaring a selector.** A module declares a selector in its `typeSelectors` by its name alone. A selector is named once across every module, unlike a type, which is named once within its module, so a selector's name identifies the module that declares it, and a module declaring a selector of a name already declared is refused at registration with a module error naming the selector and the module that declared it.
- **Its keys.** A module declares each key in its `mappings`, a **mapping** of the `selector` it belongs to, the `key` and the `type` it maps to, `{ selector: 'event', key: 'motion', type: 'Motion' }`, its key any string, as a fixed argument may give any, and its type a named type of the declaring module or one of Nexo's own written unqualified and a foreign type qualified, as [type identity](../language/types.md#types-type-identity) sets out. A mapping never writes an object's shape in place: a key whose values are objects maps to a named structured type, as `motion` maps to `Motion`, whose properties `at` and `strength` hold a motion's data. A mapping's selector and key together are its identity, and different selectors may share a key. Any module declares keys for any selector, its own or one a module registered before it declares, so one module extends another's selector as it extends another's types, and is registered after the module it extends. A key stands once in its selector across every registered module: a second, from the same module or another, is refused at registration with a module error naming the selector, the key and the module that declared it first, and no key once registered is replaced. A key of a selector no registered module declares is refused too.
- **Its revision.** Registering a module that adds keys advances the registry's revision, as every registration does; a key never replaces another, so the keys a resolution settled stay as they were, and whether it stays current is set out in [reusing a resolution](resolution.md#runtime-reuse).
- **A parameter that selects.** A function's parameter that selects through a selector is fixed and names it, `fixed: true, selects: 'type', selector: 'event'`, and its argument settles as every [fixed argument](../language/members.md#arguments-fixed) does. A function has at most one parameter that selects a type, since its `result` writes one `@selected` where the selected type stands, as `@selected` or `List<@selected>` does; a function with no parameter that selects a type writes none.
