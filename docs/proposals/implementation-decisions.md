# Implementation decisions

The decisions taken while implementing the plan from step 5 of unit 1 through unit 5 without a review of each, so the work goes on uninterrupted: each is recorded here as it is taken, with its reason and what it departs from, if anything, and all of them are reviewed together before unit 6, when any is changed. A decision that settles what the specification leaves open is recorded in the specification too, where its subject lives, and links back here until its review.

**State:** awaiting review. An entry is reviewed once it is marked ✅ reviewed, or changed as its review decides.

| I20 | Unit 2, the selector | One `MemberSelector`, which the registry owns beside its `TypeChecker`, selects among a name's declarations, or the unnamed indexers, for a receiver type, answering the declaration, the competing ones, the internal ones that alone apply, or none: the resolver reads it for a member, a named and an unnamed indexer, a qualified call, the brackets after a name, and its hints. | I21 | Unit 2, operators | An operator is a member of kind `operator`, within a type or an extension, named `cast` or `convert`, its destination its `result`, its own declaration keys `name`, `kind`, `result`, `impl` and `internal`; the registry indexes operators by name apart from the members, and a namespace reaches none. `to` and `as` select theirs among the operators of that name and destination applicable to the source, through the selector. A message names one by its receiver, its syntax and its destination, `String to Number` and `Meter as Home.Device`, and an error locates it at its module, the type or the extension it stands in, and its name. A declared cast's `impl` and a conversion's are called alike, a rejection answering the reason; a cast's other failures, a reason that is no string among them, are LEXICA5004, and a conversion's keep LEXICA5003 and LEXICA5018. | I22 | Unit 2, `Any` and deferred selection | A deferred call's arguments are values alone: one that reads its own implicit parameter, and one that gives a function, an arrow function, a local function or a function reference among them, are refused at resolution with LEXICA3029, and at evaluation a selected member's function, expression, predicate or fixed parameter given a value fails with LEXICA5012. A value's actual type is typed as a binding types it, without copying: a reference by its modules' recognition, the one beneath every other; a structured value by the declared result whose copy gave it, which the evaluator records by value; a list by the type its items share, `Any` where they share none; an object by its fields. Selection is kept per node and per actual type's qualified text within the compilation, which its resolved definition and its registry hold. A null receiver fails with LEXICA5022 unless the access is optional or an optional access before it in its chain met null, a null a deferred access's member answered never counting as one; a member that answers null where it declares `Any` fails with LEXICA5006, as any result that its type refuses does. An ambiguous selection, too many values, a value left out that is required and an options field the member has no parameter of are LEXICA5012; a value its parameter doesn't admit is LEXICA5021, as a typed call's `Any` argument is. An equality of `Any` records its operator, so its runtime refusal names it. A result holding `Any` is checked to be data once, at the result, a recognized plain object counting as a reference, and an object field of `Any` that never reaches the result is not checked | A function's reading is the declaration's: its parameters' types and its arity come from the callback contract the selected member declares, and checking a function against a contract chosen during evaluation needs the callback machinery resolution prepares, so values alone keep the deferred path to one value check per parameter; resolution already refuses an object field that is no data, so what the result alone carries out is what must be checked | The specification accepts an explicitly written function as a deferred call's argument, [deferred member selection](../../spec/types.md#types-any-deferred-selection): it waits until a host needs one |
| I23 | Unit 2, reporting | An operator a cast or a conversion selects is a used declaration, at the cast's or the conversion's pointer, named `convert` or `cast` and qualified by the syntax that invokes it, as `String to Number`, as a message names it; a cast operator, whose `impl` is optional, is never refused for lacking one, and LEXICA4001 locates every member within a type or an extension at its `type`, as its module's other errors do. A resolution's `deferredAccesses` are `{ name, pointer }`, the name null for an unnamed indexer, in the order they were resolved, each once at its definition pointer. `getCandidateDeclarations()` answers `{ declarations, isOverestimate }`: the used declarations, then each deferred access's candidates, every accessible declaration of its name and form, at its pointer and qualified by the type it is declared for, each declaration once at each pointer; `isOverestimate` is true wherever a deferred access remains, whether or not every candidate could be selected | The used declarations already carry what a host reads of a use, so an operator joins them rather than a list of its own, and a candidate reads as a use does; a candidate qualified by its declared type names it without a receiver type, which a deferred access has none of before it is evaluated; an analysis that proves which candidates a value's actual type can reach would need the types of values no resolution knows, so the report says it overestimates rather than claim precision | The specification names the reports without their shapes; their names follow the resolution's `usedDeclarations`, and a method, since candidates are reported when asked for |
| I24 | Unit 2, U1's candidates | A member of a receiver of unknown type, whose resolution keeps its candidates, compiles to its own evaluation: it evaluates its receiver once, which is null, since a receiver of the type null holds nothing else and a never is never evaluated, and answers null, evaluating none of its arguments and invoking nothing, as an access of null does. | I25 | Unit 2, a callback's answer of `Any` | A function, an implicit body, an expression's body or a function reference whose answer is of `Any` or `Any?` is accepted where its callback contract declares a result type, `Any` assignable once checked, and the callback checks each value it answers against that type, LEXICA5504, which leaves the temporary codes for the specification's catalog. | I26 | Unit 3, line endings | A separator, U+2028 or U+2029, in code is an invalid token of its one character; one in a comment makes the comment one invalid token, from its `//` or `/*` to its end, its diagnostic at the separator, LEXICA1002, the message naming the character as `U+2028, the line separator,`. A location counts a line at each LF, at a CR no LF follows, and once for CRLF, whose two characters the offset counts. In the syntax tree, a line comment's trivia holds the line break that ends it, CRLF whole, as it held an LF | Reading on from a separator's own character would read the rest of its comment as code and report what follows; a comment refused whole keeps tolerant reading's diagnostics to the one that matters. A line comment held its LF before, so each line break keeps that shape | The specification fixes the condition and its code, not where the invalid token ends or how the trivia divides |
