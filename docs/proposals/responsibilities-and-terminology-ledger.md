# Ledger: responsibilities and terminology

The review ledger of [clarify responsibilities and unify terminology](responsibilities-and-terminology.md): each concept or operation the survey of `src/`, `lexica.d.ts`, the specification, the guide and the tests found, its owner and responsibility, what its distinction means, the action proposed and its compatibility.

**Every entry is unreviewed** unless it is marked ✅ reviewed. An unreviewed entry stays as the code has it; absence of an objection approves nothing. An entry is applied only once it is reviewed.

Each entry has an identifier to review it by. Its columns carry the proposal's eight fields: the current name and location; its owner, responsibility, inputs, outputs and side effects; its relationship to other concepts and whether its distinction is meaningful or incidental; the action; its compatibility; and its dependencies and validation.

**Lands:** *P*, the prerequisite stage this ledger plans; *S1*, *S2*, the declaration model's stages 1 and 2; *unit 2*; *D34*, definition version 34 in unit 3, where every serialized change lands together. **Compatibility:** *internal*; *public* (a name a host calls or reads at runtime); *types* (`lexica.d.ts` alone); *serialized* (the definition format); *declaration* (a key a host's module writes); *wording* (a message, its code unchanged); *test*.

Line numbers are those of the survey's commit and move as entries land.

## 1. Decided

### The first review

1. ✅ **Declaration helpers** construct declaration records, so they take explicit factory verbs and subjects, `lexica.declarations.createFunctionDeclaration(…)`; `define…` only where a contract warrants it, and none does (entry M1).
2. ✅ **Runtime** names execution alone. The language defines the rules; the parser and the resolver implement them, and are no more the language than the runtime is. `versions.runtime` becomes `versions.implementation`, since it identifies the release of the whole implementation (entry C7).
3. ✅ **Public verbs:** `registry.createBindings`, `bindings.readValue`, `bindings.getType`, `lexica.getLocation` and `resolution.getLocation`, `lexica.paths.validate`, `evaluator.prepareHostCall` and `LexicaEvaluationHooks`, each shown with its owner, and each contract stating its side effects.
4. ✅ **`takesReceiver`** for a declaration's or an invocation's contract requiring a receiver, never for a record that merely holds one.
5. ✅ **Definition `member`:** never `propertyAccess` while it represents function references and indexer selection.
6. ✅ **Text verbs:** `parse`, `scan`, `quote` and `format` by their results; the verb table is no whitelist, and reading source text is reading.
7. ✅ **`namespace-name`** where a name is the local namespace an import establishes; `module-name` where it identifies the registered module, classified by occurrence (entry S7).
8. ✅ **`local-function-call`** only if every form it covers calls a local function. It doesn't, so `function-call` stays (entry S8).
9. ✅ **Result metadata `objectFields`** is a public execution change, not a serialized one, landing with its producer, consumers, types, documentation and tests.
10. ✅ **The location suffix** reads "at 'updates.misses'".
11. ✅ **`compile`** joins the verb table: transform a representation into an executable form.
12. ✅ **`prepareHostCall`**, decided with 3.
13. ✅ **Validation:** error kinds and codes stay; the difference between structural definition validation and semantic validation during resolution is documented (entry C15).
14. ✅ **Recording:** implementation conventions in the contributor instructions, semantic terms in the specification and the glossary, and this work the prerequisite stage, ahead of the dependent implementation.
15. ✅ **Accepted corrections:** `object-field` for the syntax node kind; `objectFieldValue` where a variable holds a value; `isObjectRootField` for the object root; `getDeclaringModuleName` for the declaring module's name; declaration-returning names where a lookup returns a declaration; no object-field name on an operation that still handles a structured type's data.

### The second review

1. ✅ **Definition 34's call node** is `{ kind: 'call', callee, arguments }`: a `local` node identifies a function held by a name in scope, a `memberAccess` node a receiver's or a namespace's member. It removes the split between `functionCall` and `call`, preserves the written call forms permitted today, and authorizes no call of an arbitrary expression (entry U1).
2. ✅ **The member-access node is `memberAccess`.** An object field can be accessed as a member of its object type without becoming a module-declared member, which the specification states. An implementation mapping, such as `FORM_NODE_KINDS`, is acceptable where the concepts differ (entry U2).
3. ✅ **The data read's kind is `'storedValue'`** until S1, then `'objectField'` once it represents object fields alone. The reading implementation stays shared, and the declaration migration isn't brought forward for the final name. The later transition is a tracked S1 obligation, so the temporary name can't become permanent by accident (entry U3).
4. ✅ **One invocation-scoped lifetime** for the wrappers given to module implementations, alike for explicit functions, expression bodies and implicit bodies, with their argument and result checks applied consistently; calling an expired wrapper is refused. Expiring a wrapper never invalidates the script function beneath it, its captured state, or its use in another invocation. An intentional behaviour change, documented, and tested by calls after the invocation finishes (entry U1d).
5. ✅ **What counts as data** is one rule, written first, and one predicate. The proposed rule is recursive: scalar data and null qualify; an object, list or structured value qualifies when all its constituent values do; reference values and functions don't. For a static type, every possible alternative satisfies the rule; `Never` contributes no non-data possibility, and an unconstrained unknown type can't establish that a value holds data alone. The rule is checked against the conversion contract before it applies, and no implementation is chosen for accepting more cases (entry R12).
6. ✅ **Object-typed defaults are accepted** under the ordinary compatibility rules, their fields validated against the declared type, and the copying and immutability rules applied. Registration and evaluation agree about what fits a type; a further restriction on defaults would be specified, never hidden in a competing algorithm (entry R13).
7. ✅ **Each uniqueness rule is checked at the scope that owns it:** a module-local duplicate when the module is created, a conflict with other registered modules when it is registered, each by its exact duplicate key (entry R11). A type's identity includes its module, and member checks keep the permitted overloads: one check per scope means one consistent implementation of that scope's rule, not refusing every repeated name. D5 is fixed against its established rule without waiting for the rest.
8. ✅ **Diagnostic codes stay** during this prerequisite work, while the validation machinery is shared: a shared implementation needs no shared codes. Retiring a code remains a legitimate, separate decision (entry U33).
9. ✅ **`runtime.md`'s heading is "Host contract",** its file name and anchors kept (entry C14).
10. ✅ **`registry.parse`, `format` and `quote` are removed at unit 3,** once their contracts are equivalent to the top-level ones, imports supplying the namespaces; equivalent input handling and diagnostics are confirmed before they go (entry U36).
11. ✅ **A prepared or skipped call names its node by `pointer`,** a definition pointer that `resolution.getLocation` expands, identifying the call consistently across preparation, skipping and invocation requests (entry U38).
12. ✅ **The observation type input keeps `request`,** its meaning and shape defined once (entry C10).
13. ✅ **A used declaration's qualified name is `qualifiedName`;** `name` is the declared name everywhere; `displayName` stays reserved for presentation text that may differ from both (entry C9).
14. ✅ **`#copyResult` returns an explicit result,** `{ value, copiedIdentities }`, in its single traversal: a design preference, not a defect in today's side channel (entry R17).
15. ✅ **`'objectRootField'` stays** a resolution kind, sharing the stored-value read; its selection handling justifies the distinction, and explicit object-root names stay wherever that responsibility does (entry U3).
16. ✅ **The proposal's §15 example** becomes the two type lookups, an object field's and a structured type's data shape's, which follow different type contracts though their runtime reads share an implementation; other examples implying a withdrawn API are corrected with it.

## 2. Requirements

These hold for every entry they touch.

1. **Each consolidation states the observable semantics it preserves.** A shared representation is worth having where it removes duplicated decisions; matching record shapes alone don't prove two operations equivalent.
2. **A defect fix is reviewable on its own and implemented once.** Where it supplies machinery a unification needs, D1's type-name helper (S4) and D4's default handling (U8), it is that machinery, and the unification's entry refers to it, never a temporary implementation replaced at once.
3. **D3 closes first,** before any entry relies on a registry query being internal.
4. **Confirm before calling it a defect:** each suspect of §3 is reproduced by a test first.
5. **Completion.** The prerequisite stage is done when every reviewed entry assigned to *P* is implemented and verified. Entries assigned to *S1*, *S2*, *unit 2* or *D34* stay tracked obligations of those stages, and unreviewed entries stay unchanged.
6. **Definition 34 lands whole,** readers, writers, public types, fixtures and pointers together, and definition 33 keeps its meaning.
7. **An entry may conclude "retain"** with its contract documented, where a new name would only enumerate an implementation's current contents.
